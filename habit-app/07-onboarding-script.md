## 3. 진단 결과 → 루틴 추천 매핑 표

추천 루틴은 전부 **무료 5종(§9)과 그 시간대 변형**으로만 구성한다 — 온보딩 추천 경로에서 유료 콘텐츠를 만나는 일은 없다. "그때그때"형은 저녁형 열을 따르되 권장 시각만 12:30 변형. **굵은 글씨** = S07에서 등록되는 대표 습관.

| 영역 | 아침형 추천 | 저녁형·유동형 추천 | 극소 축소 예시 (기본 → 2분 버전) |
|---|---|---|---|
| 몸 | 「미라클 모닝 스타터」: **기상 직후 물 한 잔** + 스트레칭 5분 | 「퇴근 후 리셋」: **홈트 15분** + 23:30 폰 내려놓기 | 홈트 15분 → 운동복 갈아입기 / 스트레칭 5분 → 기지개 10초 / 23:30 폰 내려놓기 → 23:00 폰 충전기에 꽂기 |
| 공부 | 「매일 25분 공부」(07:00 변형): **책상에 앉아 타이머 25분** + 영단어 10개 | 「매일 25분 공부」(21:00 변형): **책상에 앉아 타이머 25분** + 영단어 10개 | 공부 25분 → 책상에 앉아 책 펴기 / 영단어 10개 → 3개 |
| 일과 성장 | 「1쪽 성장 루틴」(아침 변형): **독서 10쪽** + 회고 한 줄 | 「1쪽 성장 루틴」(저녁 변형): **사이드 프로젝트 30분** + 회고 한 줄 | 독서 10쪽 → 1쪽 읽기 / 사이드 프로젝트 30분 → 에디터 열고 10분 / 회고 한 줄 → 한 단어 기록 |

- 루틴은 통째로 노출하되 **온보딩에서는 대표 습관 1개만 등록**한다. 나머지 습관은 D3(3일 스트릭 축하 직후)·D7(첫 주간 진입)에 루티가 하나씩 제안. 근거: 첫 주 성공률이 이후 전 지표를 결정(→ 03 문서 §1)하고, 과다 등록이 1차 타겟의 공통 좌절 경험. 대안: 루틴 3개 일괄 등록 — 04 실험 백로그에 변형으로 추가 가능하나 기본값은 1개.

## 4. "지금 바로 첫 체크" 후보 목록

분기 규칙: 대표 습관의 2분 버전에 `즉시 실행 가능` 태그(시간대 무관 행동)가 있으면 **그 습관을 지금 체크** — 오늘부로 스트릭 1일 시작. 시간 고정 습관(기상·취침·출근 전 등)이면 아래 **스타터 미션** 중 영역 일치 1개를 제시한다. 스타터 미션은 습관 슬롯을 차지하지 않는 1회성 체크로, XP +10과 루티 첫 리액션만 지급하고(Phase 0은 완료 연출만 — §1 Phase 0 변형) 스트릭과 무관하다("내일, 진짜 첫 스트릭이 시작돼요"로 명시 — 안 한 일을 한 것으로 치는 기록 왜곡 금지).

| 스타터 미션 | 소요 | 영역 |
|---|---|---|
| 물 한 잔 마시기 | 30초 | 몸 (공통 폴백 1순위) |
| 제자리에서 기지개 10초 | 10초 | 몸 |
| 오늘 외울 영단어 1개 소리 내 읽기 | 30초 | 공부 |
| 아무 책이나 지금 1쪽 읽기 | 60초 | 공부 · 일과 성장 |
| 내일 할 가장 작은 일 한 줄 쓰기 | 60초 | 일과 성장 |
| 눈 감고 심호흡 3번 | 30초 | 마음 |
| 오늘 감사한 것 1가지 쓰기 | 60초 | 마음 |

|---|---|---|---|
| 1차 유도 | **두 번째 체크인 완료 직후** | 바텀시트 (스킵 가능) | "이틀의 기록이 쌓였어요. 폰이 바뀌어도 잃지 않게, 30초만 백업해둘까요?" |
| 2차 유도 | D7 첫 접속 시 (미가입자) | 홈 상단 배너 1회 | "일주일치 정원을 백업해두세요" |
| 강제 시점 | 결제 시도(구독·프리즈 단품), 기기 변경·복원, 소셜/챌린지 기능 진입(Phase 2) | 해당 플로우 진입 시 시트 | "결제와 기록 보호를 위해 계정이 필요해요" |

- 1차 유도를 D2로 두는 근거: 첫 페이월 (a)가 "3일 스트릭 직후"(→ 02 문서 §2.3)이므로, 그 전에 계정을 확보해 같은 순간에 가입+페이월 시트가 겹치는 것을 방지한다.
- **소셜 로그인 우선순위**: 1순위 카카오(1차 타겟 커버리지 최대) → 2순위 iOS는 Apple(제3자 로그인 제공 시 앱스토어 심사 필수 + 원탭), Android는 Google → 이메일 가입은 접힌 링크. 전화번호 인증 없음(마찰만 추가).
- **게스트 데이터 이전**: 신규 가입 → 로컬 데이터 전량 서버 이관(→ 05 문서 §5.1). 기존 계정 로그인 + 게스트 기록 존재 → 병합: 체크인은 (habit_id, 날짜) 합집합(→ 06 문서 충돌 규칙 준용), 습관은 양쪽 유지하되 활성 3개 초과분은 최근 체크 순으로 자동 보관, XP·프리즈·회복권은 양쪽 중 **큰 값 채택**(합산은 멀티 기기 부풀리기 여지). 이관 실패 시 로컬 원본 보존 + 백그라운드 재시도 — 달성 기록 유실은 절대 금지.

## 6. 알림 권한 요청 각본

2단 구조: **프리퍼미션(자체 화면 S11) → OS 다이얼로그(S12)**. OS 다이얼로그는 프리퍼미션 수락자에게만 노출한다. 근거: iOS는 1회 거부 시 설정 앱까지 가야 복구되므로, 확률 낮은 시점에 OS 기회를 소진하지 않는다.

- 가치 프레임 카피(S11): "내일 몇 시에 루티가 깨워드릴까요? 잔소리는 안 해요 — 「운동복 갈아입기」 시간에 딱 한 번만." (권한이 아니라 "약속 시간"을 묻는 프레임, 기본값은 Q3 매핑 시각)

| 거부 지점 | 폴백 |
|---|---|
| S11에서 "알림 없이 할게요" | OS 다이얼로그 미노출(기회 보존) → S13 위젯 카피 강화판 노출("알림 대신, 홈 화면이 기억해줄 거예요") |
| S12 OS 다이얼로그 거부 | 동일 폴백 + 이후 재요청 시 설정 앱 딥링크 안내 필요 플래그 |
| 재요청 1차 | 3일 스트릭 축하 직후 — "내일 4일째를 지키고 싶다면, 시간 맞춰 알려드릴까요?" |
| 재요청 2차 | 첫 미스 후 복귀 시점 — "다음엔 놓치기 전에 살짝 알려드릴게요" |
| 그 이후 | 인앱 재요청 금지. 설정 화면에서만 켤 수 있음 |

발송 시각 학습·피로 관리·문구 운영 → 03 문서 §6.

## 7. 온보딩 상태 머신 — 단방향 보장

```
WELCOME → Q1 → Q2 → Q3 → ANALYZE → RECOMMEND → CONFIRM_HABIT
       → SHRINK → FIRST_CHECK → REWARD → NOTIFY_PRIME → (NOTIFY_OS) → WIDGET → DONE
```

1. **전이는 위 순서로만 전진한다.** 뒤로가기는 Q1~Q3 구간의 이전 문항 이동만 허용. RECOMMEND 이후의 "수정"은 전부 화면 내 대체 액션(다른 루틴 보기, 습관 교체 모달)으로 처리 — 상태 후퇴 전이는 존재하지 않는다.
2. NOTIFY_PRIME 거부·FIRST_CHECK 스킵·WIDGET 스킵은 모두 **전진 전이**다. 어떤 선택도 이전 상태로 되돌리지 않는다.
3. 매 전이마다 상태+입력값을 로컬 영속화. 크래시·강제 종료 후 재실행 시 저장 지점부터 재개(`onboarding_resumed` 이벤트).
4. DONE 도달 시 `onboarding_completed` **영구 플래그**를 기록하고 온보딩 스택을 파기한다. 이후 딥링크·푸시·화면 복원·페이월 닫기 등 어떤 경로로도 온보딩 화면은 재진입 불가 — 온보딩 컴포넌트가 렌더 전에 플래그를 검사해 홈으로 리다이렉트한다. **Pillar의 "루틴 선택 ↔ 구독 화면 무한 루프" 버그(→ 01 문서 §2 반면교사)가 이 규칙의 존재 이유다.**
5. 온보딩 상태 머신 안에 페이월 상태는 없다(Phase 0·1 공통). 페이월은 DONE 이후 02 문서의 3개 타이밍에서만 별도 플로우로 뜬다 — 온보딩과 결제 플로우는 상태를 공유하지 않는다.
6. ANALYZE의 추천 계산은 §3 로컬 매핑 표로 수행한다. 서버 응답 대기 상태를 두지 않으므로 네트워크로 인한 온보딩 멈춤이 원천 차단된다.
7. 휴면 복귀 유저의 "복귀 온보딩"(습관 1개 재시작, → 03 문서 §8)은 이 머신을 재사용하되 WELCOME·Q1~Q3를 스킵하고 RECOMMEND(이전 데이터 기반)부터 시작하는 별도 인스턴스다.
