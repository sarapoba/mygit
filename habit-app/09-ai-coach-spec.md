# 09. AI 코치 명세

> AI 코치(명칭: **정원사**)의 페르소나·기능 4종·컨텍스트 구성·비용·안전 규칙의 SSOT.
> 알림 총량·발송 시각 학습·피로 관리 → 03 문서 §6, 티어 경계·가격 → 02 문서, 스트릭·프리즈·2분 버전 산식 → 06 문서, 루티 대사·화자 규칙 → 08 문서, 코치 카드 화면 배치 → 11 문서, 이벤트 스키마 → 12 문서 참조.
> 기능 4종은 전부 **Phase 1** 범위(AI 코치 v1). Phase 0에는 AI가 없다(→ 04 문서 §1).

## 1. 코치 페르소나 — "정원사"

| 항목 | 확정 |
|---|---|
| 명칭 | **정원사** — 고유명 없는 역할명. 인앱 표기 "정원사", 푸시는 앱 명의 발신. 근거: 세계관("우리의 정원", → 07 문서 S14) 정합 + 제2의 고유명 캐릭터는 루티 애착을 분산시킴(→ 08 문서 §1 원칙 1과 동일 논리). 대안: 무명 "AI 코치" 라벨 — 세계관 이탈이라 배제 |
| 정체성 | 유저와 함께 루티를 돌보는 관찰자. 데이터를 읽고 **다음 한 걸음**을 제안한다. 감정·애착은 루티 담당, 정원사는 관찰과 제안 담당 — 역할 분리(→ 08 문서 §3.1) |
| 말투 | 차분한 해요체. 기본 골격 = **관찰 1문장 + 제안 1문장**. 호칭·닉네임 미사용(주어 생략 — §3 개인정보 최소화와 연결), 이모지 미사용(루티 표면과의 시각적 구분 장치) |
| 화자 경계 | 루티 1인칭 대사("나 ~") 생성 금지(→ 08 문서 §5). 루티는 3인칭 언급만 가능("루티가 기다렸어요"). **손실 프레이밍은 밤 21시 스트릭 위험 알림 템플릿 전용**(→ 03 문서 §6) — AI 생성 카피에서는 금지. 챌린지 환급선 임박 고지(→ 10 문서 §9)는 챌린지 시스템 명의 정적 템플릿으로 AI 생성 경로 밖 |
| AI 고지 | 첫 코치 카드 하단 + 설정 화면 상시 노출 (§5.3) |
| v1 범위 | 자유 대화(챗) 없음 — 기능 4종의 시스템 발화만. 근거: 가드레일 면적 최소화 + Phase 1 게이트 집중. 대안: 챗은 Phase 2에서 별도 검토 |

### 1.1 해도 되는 말 / 안 되는 말

| 해도 되는 말 | 안 되는 말 |
|---|---|
| 데이터 관찰 서술 — "7번 중 2번이었어요" | 평가·비난 — "겨우", "또", "아직도" 등 08 문서 §5 금지어 전체 준용 |
| 2분 버전·시간대 이동·주기 완화 **제안**(항상 선택지 형태) | 명령형 종결 — "하세요", "~해야죠" |
| 프리즈·회복 규칙 안내, 마일스톤 카운트다운(긍정 프레임: "21일까지 이틀") | 손실 프레이밍 — "안 하면 스트릭이 끊겨요/사라져요" |
| 회복·복귀 환영, 부분 달성의 동등 인정(→ 06 문서 §5) | 의료·정신건강·법률·재무 조언, 진단명 추정("우울/번아웃 같아요") |
| 입력 컨텍스트에 **존재하는** 수치·습관명 인용 | 입력에 없는 수치·사실 생성, 확정적 예언("반드시 성공해요") |
| 루티 3인칭 언급 | 사람·전문가 자칭, 부재 기간 책망("3일이나 안 오셨네요"), 밀린 기간 언급(→ 08 문서 §3.1) |

## 2. 기능 4종 명세

| 기능 | 무료 | 프리미엄 | 채널 | 빈도 상한 |
|---|---|---|---|---|
| 아침 브리핑 | 없음 (습관 리마인더 템플릿만 → 03 문서 §6) | 매일 AI 생성 + 온디맨드 재생성 | 푸시 + 홈 상단 카드 | 일 1회 (재생성 별도) |
| 미루기 개입 | 동일 트리거, **정적 템플릿 풀**(§7) 발송 | AI 개인화 카피 | 푸시 (앱 사용 중이면 인앱 배너) | 일 1회, 습관당 주 2회 |
| 주간 리포트 코멘트 | 주 1회 경량 요약 — **캐논의 "AI 주 1회 요약"이 바로 이것** | 심화 코멘트(상관 인사이트 포함) | 인앱(리포트 화면 내) | 주 1회 |
| 난이도 하향·상향 제안 | 제공 | 제공 | 인앱 카드만 | 유저당 주 1회, 습관당 14일 쿨다운 |

- 미루기 개입의 티어 분리 근거: 02 문서 §2.1에서 AI 생성은 프리미엄이지만, 개입 **장치 자체**는 03 문서 §6의 전 유저 대상 알림 전략이다 — 무료는 템플릿, 유료는 AI 카피로 정합시킨다.
- 하향 제안은 이탈 방지 장치(→ 03 문서 §8)이므로 용서 장치와 같은 원칙으로 **티어로 잠그지 않는다.** 빈도 상한이 있어 원가 영향은 무시 가능(§4).
- 모든 생성은 **서버 사이드 전용** — 클라이언트가 모델 API를 직접 호출하지 않는다(키 노출·가드레일 우회 방지).

### 2.1 아침 브리핑

| 항목 | 확정 |
|---|---|
| 트리거 | 프리미엄 + 오늘 due 습관 ≥ 1 + 푸시 허용 + 알림 하향 상태 아님(§8). due 0개면 미발송 |
| 발송 시각 | 초기값 아침형 07:00 / 저녁·유동형 08:00 → 최근 14일 "06:00~10:00 첫 앱·위젯 활성 시각" 중앙값으로 학습 이동. 습관 리마인더와 동시각이면 푸시 1건으로 병합(브리핑이 리마인더 대체) |
| 생성 시점 | 매일 04:10~05:30 새벽 배치(하루 경계 판정 직후, → 06 문서 §4.2). 온디맨드 "다시 계획하기"(습관 편집·체크 후)만 실시간 재생성 |
| 입력 필드 | user, today, habits[](streak·next_milestone·last14·usual_check_hour), resources — §3 데이터 사전 |
| 출력 형식 | JSON `{headline≤24자, body≤90자, focus_habit_id, cta("check"\|"open_habit")}` — headline은 푸시 제목, body는 홈 카드 본문 |

예시 1 (평상): headline "오늘의 시작은 「운동복 갈아입기」" / body "어제 3개 모두 달성했어요. 오늘은 「물 한 잔」과 「홈트 15분」 — 홈트는 19일째, 21일까지 이틀이에요."
예시 2 (전일 프리즈 소모): headline "괜찮아요, 프리즈가 지켰어요" / body "어젯밤은 프리즈가 대신 지켰어요(남은 3개). 오늘 「타이머 25분」은 평소대로 21시가 좋겠어요. 2분부터면 충분해요."

### 2.2 미루기 개입

| 항목 | 확정 |
|---|---|
| 트리거 | ① 해당 습관의 usual_check_hour(최근 14일 체크 시각 중앙값, 표본 ≥ 5) 존재 ② 중앙값+90분 경과 시점에 미체크 ③ 오늘 개입 미발송 ④ 습관당 이번 주 개입 < 2회 ⑤ 알림 하향 상태 아님. 표본 < 5이면 개입 없음(고정 리마인더만, → 03 문서 §6) |
| 21시 알림과의 관계 | usual_check_hour ≥ 19:00인 저녁 습관은 개입 미발송 — **밤 21시 스트릭 위험 알림(03 문서 소관 템플릿)이 개입을 겸한다.** 이중 발송 금지 |
| 생성 시점 | 새벽 배치에서 **조건부 사전 생성**(발송 시점 조건 충족 시 발송, 이미 체크됐으면 폐기) — 실시간 호출 없음 |
| 입력 필드 | 대상 습관 1개(name·mini_name·streak·last14·지연 시간), resources |
| 출력 형식 | 푸시 본문 1문장(≤ 55자) + 딥링크(해당 습관의 2분 버전 제안 시트). 2분 버전 제안이 기본 골격, 손실 프레이밍 금지 |

예시 1: "평소라면 홈트를 시작했을 시간이에요. 오늘은 「운동복 갈아입기」까지만 해도 19일이 이어져요."
예시 2: "책상에 앉는 것까지가 오늘의 전부여도 돼요. 타이머는 2분만 걸어봐요."

### 2.3 주간 리포트 코멘트

| 항목 | 확정 |
|---|---|
| 트리거 | 매주 일요일 18:00 배치 생성(집계 범위: 월 04:00~일 18:00 스냅샷, 이후 체크는 다음 주 반영) → 20:00 리포트 발행. 리포트 도착 푸시는 03 문서 소관 템플릿(AI 아님) |
| 대상 | 이번 주 체크인 ≥ 1회 유저. 0회 유저는 코멘트 없이 리포트만(부재 책망 문구 원천 차단) |
| 입력 필드 | week(done·due·delta_pp·best_slot·quest_progress), habits[], 프리미엄만 corr_pairs[] + opt-in 시 reflections[] |
| 출력 형식 | JSON `{comment≤120자, suggestion≤60자}` — 리포트 화면 상단 고정. 무료는 경량 모델 요약, 프리미엄은 상관 인사이트 1개 필수 포함 |

예시 1 (무료): comment "이번 주 12번 중 9번 체크인했어요. 아침 「물 한 잔」은 한 번도 빠지지 않았고, 주말에 쉬어 가는 패턴이에요." / suggestion "다음 주 토요일 「홈트」는 2분 버전으로 가볍게 시작해봐요."
예시 2 (프리미엄): comment "달성률 82%, 지난주보다 11%p 올랐어요. 「홈트 15분」을 한 날은 「타이머 25분」 완료율이 30%p 높았어요 — 운동이 공부의 스위치예요." / suggestion "다음 주엔 홈트를 공부 직전 시간대로 붙여보는 걸 추천해요."

### 2.4 난이도 하향·상향 제안

07 문서 §9의 "강도 상향은 AI 제안으로(하향 제안과 동일 채널)"를 이 기능에 통합한다 — 하향과 상향은 같은 카드 포맷의 양방향이다.

| 항목 | 확정 |
|---|---|
| 하향 트리거 | 최근 7일(due ≥ 4인 습관 대상) 달성률(부분 포함) ≤ 40%, 또는 프리즈 0 + 회복권 소진 상태에서 미스 발생. 이미 2분 버전이 기본인 습관은 주기 완화(주N회 하향) 또는 7일 일시정지(→ 06 문서 §6)를 대신 제안 |
| 상향 트리거 | 2분 버전 사용 중 + 최근 14일 달성률 ≥ 80% → 기본 버전 복귀 제안 |
| 상한 | 유저당 주 1회, 습관당 14일 쿨다운. 거절 시 동일 습관 재제안은 쿨다운 2배 |
| 채널 | **인앱 카드만**(다음 앱 진입 시 홈 상단). 푸시 금지 — 이탈 위험 유저에게 푸시 추가는 03 문서 §6 피로 관리와 상충 |
| 출력 형식 | JSON `{diagnosis≤60자, proposal≤80자, action("shrink"\|"reduce_freq"\|"pause7"\|"restore"), cta_accept, cta_keep}` — 수락 시 원탭으로 습관 설정 자동 변경 |

예시 1 (하향): diagnosis "최근 7일, 「홈트 15분」이 7번 중 2번이었어요. 요즘 하루에 15분이 큰 것 같아요." / proposal "이번 주는 「운동복 갈아입기」(2분 버전)를 기본으로 바꿔볼까요? 스트릭과 잔디는 똑같이 인정돼요." / CTA [2분 버전으로 줄이기] [지금대로 할게요]
예시 2 (상향): diagnosis "「운동복 갈아입기」로 줄인 지 2주, 14번 중 12번을 해냈어요." / proposal "원래 크기 「홈트 15분」으로 돌아가도 좋은 페이스예요. 물론 지금대로도 충분해요." / CTA [15분으로 되돌리기] [지금대로]

## 3. 컨텍스트 구성 명세

프롬프트 3단 구조: **① system(고정 — 페르소나 §1 + 가드레일 §5 + 출력 스키마 + 금지어. 프롬프트 캐시 대상) ② context(가변 JSON, 아래 사전) ③ task(기능별 지시 템플릿).**

| 블록 | 필드 | 비고 |
|---|---|---|
| user | tier, days_since_join, diagnosis{area, time, chrono}, locale | 식별자(닉네임·이메일 등) 일절 미포함 |
| today | date, weekday, due_habits[] | 하루 경계 04:00 기준(→ 06 문서 §2) |
| habits[] | habit_id, name, mini_name(2분 버전), type, streak, next_milestone, last14, usual_check_hour | last14 = 14자 문자열, `O`완전 `P`부분 `F`프리즈 `R`회복 `X`미스 `-`비due |
| resources | freeze, recovery_left | 정의 → 06 문서 §4.1 |
| week | done, due, delta_pp, best_slot, quest_progress, corr_pairs[](프리미엄) | 주간 코멘트에만 투입 |
| reflections[] | 최근 7건, 건당 100자 절단 | **opt-in 시에만**(아래 원칙 3) |

**개인정보 최소화 5원칙 (확정)**

1. 실명·닉네임·이메일·전화번호·기기ID·광고ID·IP·위치는 프롬프트에 절대 미포함. 호칭 없는 문장을 생성한다(한국어 주어 생략으로 자연스럽게 해결).
2. 요청 로그의 유저 식별자는 해시 처리. 프롬프트·출력 로그는 30일 보관 후 파기(품질 리뷰 샘플은 가명화 후 별도 보관).
3. 한 줄 회고(자유 텍스트)는 **기본 제외.** 설정에서 opt-in한 프리미엄 유저의 주간 코멘트에만 포함.
4. 습관명·커스텀 루틴명은 자유 입력이라 개인정보가 섞일 수 있다 — 코칭에 필수라 프롬프트에는 넣되, 모델 학습 사용 금지·프롬프트 외 용도 사용 금지.
5. 외부 모델 API 사용 시 zero-retention(입력 미보존·학습 미사용) 계약 조건을 벤더 선정 요건으로 한다.

## 4. 비용 설계

### 4.1 티어별 제공량과 원가 상한

| 항목 | 무료 | 프리미엄 |
|---|---|---|
| 월 생성 호출(유저당) | 주간 요약 ~4.3회 + 하향 제안 ~2회 | 브리핑 ~30 + 개입 사전 생성 ~10 + 주간 4~5 + 하향·상향 ~2 + 온디맨드 재생성 |
| 생성 방식 | 배치 100% | 배치(브리핑·개입·주간) + 실시간(온디맨드만) |
| **월 원가 상한 목표** | **≤ 15원/유저** | **≤ 300원/유저** — 연간 구독 월환산 3,250원의 10% 이내(02 문서 "AI 원가 방어" 정합) |

- 토큰 예산 가이드: 브리핑 입력 ~1.2k(캐시 제외 가변부 ~400)·출력 ~120, 개입 입력 ~800·출력 ~60, 주간 입력 ~2k·출력 ~200.
- 월 원가가 상한의 80% 도달 시 알람 → 대응 순서: ① 버킷 캐시 적중률 상향 ② 상위 모델 비중 축소 ③ 온디맨드 어뷰즈 가드(시간당 10회 — 봇 방지 수준, "매일 무제한" 정책 훼손 아님). **기능 차단·무제한 철회는 대응 수단이 아니다.**

### 4.2 모델 티어링

| 출력 | 모델 | 근거 |
|---|---|---|
| 아침 브리핑, 무료 주간 요약, 폴백 재생성 | 경량 모델 | 정형 골격 + 짧은 문장. 버킷 캐시 대상이라 물량이 가장 큼 |
| 미루기 개입, 프리미엄 주간 코멘트, 하향·상향 제안 | 상위 모델 | 뉘앙스 실패(비난 톤) 비용이 큰 카피. 발생 빈도가 낮아 원가 영향 작음 |
| 위기 신호 분류(§5.2) | 키워드 사전 + 경량 분류기 | 전 입력 검사라 초저비용 필수 |

### 4.3 캐싱·배치 전략

1. **새벽 배치 집중**: 브리핑·개입 카피를 04:10~05:30 배치 API(할인 창구)로 일괄 생성. 실시간 호출은 온디맨드 재생성뿐.
2. **프롬프트 캐시**: system 고정부(페르소나+가드레일+스키마)는 전 요청 공유 캐시.
3. **상태 버킷 캐시**: 브리핑을 상태 시그니처(전일 결과 조합 × due 수 × 마일스톤 근접 × 프리즈 소모 여부)로 버킷화 — 버킷당 일 1회만 생성하고 습관명·수치는 슬롯 치환. 목표 적중률 70%+. 시그니처가 같으면 문장이 같아도 무방하다(습관명이 다르면 유저 체감은 개인화).
4. 검증 실패 시 재생성은 1회로 제한, 재실패는 템플릿 폴백(§7).

## 5. 안전 가드레일

### 5.1 역할 경계

- 정원사의 조언 범위는 **습관 관리(크기·시간대·주기·회복)로 한정**한다(05 문서 Non-goal #10 준용). 의료·정신건강·영양 처방·법률·재무 조언은 시스템 프롬프트에서 금지하고 §6.1 출력 검증에서 이중 차단.
- 건강 관련 습관(운동·수면 등)에 대해서도 "몸이 신호를 보내면 전문가와 상의하세요" 수준의 일반 안내까지만.

### 5.2 위기 신호 감지

| 항목 | 확정 |
|---|---|
| 검사 대상 | 유저 입력 텍스트 전부 — 한 줄 회고, 습관명, 커스텀 루틴명, 온디맨드 요청. 입력단(프롬프트 투입 전)과 출력단 2회 검사 |
| 감지 방법 | 자해·자살 관련 키워드 사전 1차 + 경량 분류기 2차 |
| 동작 | ① 해당 텍스트는 프롬프트에서 즉시 제외 ② AI 생성 중단, 아래 위기 안내 카드를 인앱 1회 노출 ③ **푸시로는 절대 발송하지 않음**(잠금화면 민감정보 노출 방지) ④ 30일 내 2회 이상 감지 시 개인화 생성을 템플릿 모드로 전환 + 안내 카드를 설정에서 상시 접근 가능하게 유지 |
| 카드 문구(확정) | "혼자 견디기 무거운 마음이라면, 전문가와 이야기해보세요. 자살예방 상담전화 109 (24시간) · 정신건강 위기상담 1577-0199. 루트는 의료·상담 서비스가 아니에요." |
| 금지 | 위기 주제에 대한 어떤 코칭·위로 문구도 생성 금지 — 고정 카드 문구만 사용. 어설픈 생성 위로가 최악의 리스크다 |

### 5.3 AI 고지 — 코치 사칭 방지

- 첫 코치 카드 하단과 설정 > AI 코치에 상시 표기: **"정원사는 AI가 만드는 코치예요. 의료인·심리상담사가 아니며, 조언은 습관 관리에 한정돼요."**
- 출력이 사람·전문가를 자칭하는 표현("제가 상담사로서", "의사로서")은 §6.1 검증에서 리젝.
- 코치 카드에는 "AI" 배지를 UI 상수로 부착(생성 문구에 의존하지 않는 고지 — 배치 → 11 문서).

## 6. 품질 평가

### 6.1 룰 기반 자동 검증 (모든 출력, 실패 시 재생성 1회 → 템플릿 폴백)

1. JSON 스키마·필드별 길이 상한 준수
2. 금지어 사전 — 08 문서 §5 금지어 + 명령형 종결 + 의료·진단 단어 + 손실 프레이밍 패턴("끊겨요", "잃어요", "사라져요")
3. **참조 무결성**: 출력 속 습관명·숫자를 추출해 입력 컨텍스트와 대조 — 입력에 없는 값이면 리젝(할루시네이션 차단)
4. 화자 규칙: 루티 1인칭 화법("나 ~", "내가 ~") 미출현
5. 사람·전문가 자칭 표현 미출현 (§5.3)
6. 이모지 미출현 (§1 톤 규칙)

### 6.2 샘플링 리뷰와 운영 지표

- **주간 샘플링 리뷰**: 기능별 무작위 50건(가명화)을 루브릭 3축 — 톤 준수 / 사실 정확 / 실행 가능성 — 각 5점으로 평가. 축 평균 4.2 미만이면 해당 기능 프롬프트 개정 후 재측정.
- 유저 신호: 코치 카드에 "도움됐어요 / 숨기기" 2버튼. 이벤트(`coach_briefing_sent/opened`, `coach_intervention_converted`, `coach_downshift_accepted`, `coach_feedback_negative`, `coach_fallback_used`)는 12 문서 컨벤션 준용.

| 지표 | 목표 | 비고 |
|---|---|---|
| 브리핑 푸시 오픈율 | ≥ 12% | 미달 시 발송 시각 학습 로직부터 점검 |
| 개입 후 2시간 내 해당 습관 체크 전환율 | ≥ 25% | 무개입일 자연 전환율과 코호트 비교 |
| 하향 제안 수락률 / 수락자 2주 후 달성률 개선 | ≥ 40% / +20%p | 이탈 방지 효과의 직접 지표(→ 03 문서 §8) |
| 코치 카드 "숨기기" 비율 | < 3% | 초과 시 톤 리뷰 소집 |
| 자동 검증 리젝률 | < 5% | 초과는 프롬프트 결함으로 취급 |

## 7. 폴백 — 생성 실패 시 템플릿

폴백 템플릿은 서버 수치 슬롯 치환만 하므로 §6.1의 참조 무결성이 구조적으로 보장된다. 폴백 사용은 전량 이벤트 로깅.

| 기능 | 발동 조건 | 템플릿(슬롯 치환) |
|---|---|---|
| 아침 브리핑 | 배치 05:30까지 미생성 / 검증 2회 리젝 | "오늘 할 일 {n}개 — 「{habit}」부터예요. {streak}일째, 오늘도 2분이면 시작돼요." |
| 미루기 개입 | 사전 생성분 없음 / 리젝 | "평소 「{habit}」 시간이에요. 오늘은 2분 버전이면 충분해요." — 무료 티어 템플릿 풀(6종 로테이션, 동일 습관 연속 중복 금지)과 공용 |
| 주간 코멘트 | 배치 실패 | "이번 주 {done}/{due} 체크인했어요. 자세한 흐름은 그래프에서 확인해보세요." |
| 하향·상향 제안 | 리젝 | 정형문 생성: "최근 7일 「{habit}」 {done}/{due}회였어요. 「{mini}」(2분 버전)로 줄여볼까요?" — 진단·제안이 수치 슬롯만으로 성립하므로 룰 기반으로 충분 |
| 위기 신호 감지 시 | §5.2 | 모든 템플릿 대신 위기 안내 카드 고정 문구 |
