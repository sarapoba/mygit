# 13. MVP 백로그 및 스프린트 계획

> Phase 0(2개월 = 2주 × 4스프린트)의 실행 계획. 무엇을 만들지는 05~07 문서가 정의하고, 이 문서는 **어떤 순서로, 누가, 무엇이 통과 기준인지**를 확정한다. 게이트 수치는 04 문서와 동일: **베타 D7 ≥ 15%, 첫 주 체크인 완료율 ≥ 50%**.

## 1. Phase 0 스프린트 계획 (8주)

| 스프린트 | 목표 | 포함 스토리 | 데모 기준 (금요일 데모에서 이것이 안 되면 미완료) |
|---|---|---|---|
| **S1** (1~2주) | 코어 루프 골격 + 기술 리스크 제거 | B1, B2, C1, E1 + **위젯 스파이크**(D-스파이크) | 오프라인(비행기 모드)에서 습관 생성→원탭 체크→스트릭 증가가 동작. iOS/Android 위젯에서 로컬 DB 읽기·원탭 체크 기술 검증 완료(불가 시 딥링크 폴백 확정) |
| **S2** (3~4주) | 온보딩 + 용서 장치 | A1, A2, A3, A4, B3, C2, C3 | 신규 설치→3분 내 첫 체크 완료(스톱워치 실측). "하루 놓침" 시나리오에서 프리즈 자동 소모·회복 체크가 명세(06)대로 동작. 온보딩 완주 자동 테스트 통과 |
| **S3** (5~6주) | 위젯 + 알림 + 계측 | D1, D2, D3, E3, 알림 v0(고정 시각+3일 무반응 하향) | 앱 미실행 상태에서 위젯 원탭 체크→앱 진입 시 반영. Amplitude에 핵심 이벤트 전체 적재 확인. **6주차 말 프렌즈 베타(50명) 배포** |
| **S4** (7~8주) | 베타 하드닝 + 게이트 준비 | C4, E2, E4 + 엣지 테스트셋 전수(자정·시간대·기기변경), 크래시 프리 99.5%+(Phase 0 베타 잠정 기준 — 정식 출시 기준은 99.8%, 05 §5.2) | 공개 베타 빌드(TestFlight/Play 내부 테스트) 배포. 게이트 대시보드(D1/D7/첫 주 완료율 코호트 차트) 가동. 온보딩·스트릭 회귀 테스트 0건 실패 |

- 각 스프린트 데모는 **실기기 + 비행기 모드**로 진행한다(에뮬레이터 데모 불인정).
- 루티 캐릭터·XP·페이월은 Phase 0에 없다(04 문서 범위 준수). 체크 연출은 햅틱+애니메이션 최소본만.

## 2. 에픽 → 유저 스토리 분해

스토리 완료 정의(DoD) 공통: AC 전체 통과 + 분석 이벤트 계측 + 비행기 모드 시나리오 통과.

### 에픽 A. 온보딩 (각본·카피 상세 → 07 문서)

- **A1. 진단→루틴 추천→2분 축소 플로우**
  - AC1: Given 신규 설치 첫 실행, When 3문항 진단 완료, Then 추천 루틴이 제시되고 각 습관에 "2분 버전"이 함께 표시된다.
  - AC2: Given 진단 도중 앱 강제 종료, When 재실행, Then 마지막 답변 지점부터 재개된다(처음으로 되돌리지 않음).
  - AC3: Given 온보딩의 임의 화면, When 뒤로가기·중단·재진입을 반복, Then 동일 화면 무한 반복이 발생하지 않는다(단방향 상태 머신 — §6 원칙 1).
- **A2. 즉시 첫 체크 (aha-moment)**
  - AC1: Given 습관 확정 직후, When "지금 바로 할 수 있는 것" 제안을 수락, Then 그 자리에서 첫 체크가 기록되고 완료 연출이 재생된다.
  - AC2: Given 설치 시점부터 계측, When 첫 체크 완료, Then `first_checkin_completed` 이벤트(→ 07 §8·12 §4)에 소요 시간(초)이 기록된다(목표 중앙값 180초 이하).
- **A3. 게스트 모드**
  - AC1: Given 계정 없음, When 온보딩~체크~스트릭 전 기능 사용, Then 가입 요구 없이 전부 동작한다(익명 ID 발급).
  - AC2: Given 게스트로 7일 사용, When 가입(계정 승격), Then 습관·체크 기록·스트릭이 전부 보존된다.
- **A4. 알림 권한 가치 프레임 요청**
  - AC1: Given 첫 체크 완료 직후, When 알림 권한 요청, Then "내일 아침 몇 시에 깨워드릴까요?" 프레임의 사전 화면이 OS 팝업보다 먼저 노출된다.
  - AC2: Given 권한 거부, When 온보딩 계속, Then 흐름이 막히지 않고 위젯 설치 안내로 대체된다.

### 에픽 B. 습관 코어 (규칙 상세 → 06 문서)

- **B1. 습관 생성·편집·보관 (무료 3개 제한)**
  - AC1: Given 습관 3개 보유, When 4번째 추가 시도, Then 생성이 차단되고 "곧 열릴 예정" 안내만 노출된다(Phase 0에는 페이월 없음 — Phase 1에서 페이월 트리거 b로 교체).
  - AC2: Given 습관 보관(아카이브), When 목록 조회, Then 스트릭·기록은 보존된 채 오늘 목록에서만 제외된다.
- **B2. 원탭 체크인·체크 취소**
  - AC1: Given 오늘 미체크 습관, When 탭 1회, Then 체크 완료까지 추가 확인 팝업이 없다.
  - AC2: Given 오늘 체크 완료, When 당일 내 취소, Then 스트릭·통계가 체크 전 상태로 복원된다(익일 이후 취소 불가).
  - AC3: Given 오프라인, When 체크, Then 즉시 반영되고 온라인 복귀 시 자동 동기화된다.
- **B3. 부분 달성(2분 버전) 체크**
  - AC1: Given 습관 체크 UI, When 길게 눌러 "2분 버전만 했어요" 선택, Then 스트릭 유지 목적의 달성으로 인정되고 `partial`로 기록된다.
  - AC2: Given 부분 달성한 날, When 잔디 통계 조회, Then 완전 달성과 시각적으로 구분되되 "실패"로 표기되지 않는다.

### 에픽 C. 스트릭·프리즈 (판정 규칙 상세 → 06 문서)

- **C1. 스트릭 계산 엔진**
  - AC1: Given 체크인 이벤트 로그, When 습관별·전체 스트릭 조회, Then 저장값이 아닌 로그 재계산 결과가 표시되고, 동일 로그면 어느 기기에서도 동일 값이다.
  - AC2: Given 23:59 체크, When 자정 경과, Then 체크는 로컬 날짜 기준 전일로 판정된다.
  - AC3: Given 타임존 변경(여행)으로 하루 중복/공백 발생, When 스트릭 판정, Then 06 엣지 4·5 규칙대로 판정된다(소실일 PASS·프리즈 미소모, 중복일 1일 1회만 인정).
- **C2. 프리즈 사전 장착·자동 소모 (무료 월 1개)**
  - AC1: Given 프리즈 1개 장착 상태에서 어제 미체크, When 오늘 앱/위젯 확인, Then 프리즈가 자동 소모되어 스트릭이 유지되고 소모 사실이 비난 없는 톤으로 고지된다.
  - AC2: Given 매월 1일, When 무료 프리즈 지급, Then 보유 상한(무료 2개 — 월 지급량 1개와 별개, 06 §4.1)을 초과 적립되지 않는다(조각 조립·이월분 포함).
- **C3. 회복 체크 ("한 번은 사고" 룰, 월 1회)**
  - AC1: Given 프리즈 없이 어제 미체크(당월 첫 사고), When 오늘 체크, Then "회복 체크"로 스트릭이 유지되고 당월 사용 완료로 표시된다.
  - AC2: Given 당월 이미 사용, When 재차 미체크, Then 스트릭은 끊기되 화면에 죄책감 카피 없이 재시작 안내만 노출된다(§6 원칙 4).
- **C4. 마일스톤 연출 (7/21/66일)**
  - AC1: Given 스트릭 7·21·66일 도달, When 해당일 체크, Then 마일스톤 연출이 1회만 재생되고 `streak_milestone_reached` 이벤트가 적재된다.
  - AC2: Given 66일 도달, When 연출 종료, Then "습관 졸업" 상태로 전환되고 다음 습관 추천이 노출된다(→ 03 문서 §7).

### 에픽 D. 위젯 (계기 축 — 알림보다 우선 투자, 04 리스크 레지스터 대응)

- **D1. iOS 홈 위젯 (WidgetKit)**
  - AC1: Given 홈 위젯 설치, When 오늘 습관 상태 변경(앱/위젯 어느 쪽이든), Then 위젯이 15분 내 갱신된다(체크 직후엔 즉시).
  - AC2: Given iOS 17+, When 위젯에서 체크 버튼 탭, Then 앱 실행 없이 체크가 기록된다(App Intents). iOS 16은 딥링크로 체크 화면 직행 폴백.
- **D2. iOS 잠금화면 위젯**
  - AC1: Given 잠금화면 위젯 설치, When 잠금 상태에서 확인, Then 오늘 남은 습관 수·스트릭이 표시된다.
  - AC2: Given 위젯 탭, When 잠금 해제, Then 오늘 화면으로 직행한다(3탭 이내 체크 가능).
- **D3. Android 홈 위젯 (Glance)**
  - AC1: Given 홈 위젯 설치, When 위젯에서 체크 탭, Then 앱 실행 없이 체크가 기록되고 위젯이 즉시 갱신된다.
  - AC2: Given 제조사 배터리 최적화 환경(삼성 기준 실기기 테스트), When 24시간 방치, Then 날짜 전환이 위젯에 반영되어 있다.

### 에픽 E. 데이터 기반 (동기화·계측)

- **E1. 로컬 우선 저장소 + 체크인 이벤트 로그**
  - AC1: Given 네트워크 없음, When 모든 Phase 0 기능 사용, Then 기능 손실이 0건이다.
  - AC2: Given 체크인 기록, When 저장, Then append-only CheckIn 원장(habit_id, local_date, grade[full|partial|bonus], client_ts, device_id)으로 저장되고 수정·삭제는 취소 이벤트 추가로만 처리된다(프리즈 소모·회복은 CheckIn이 아닌 별도 원장 FreezeLedger·RecoveryCredit + 파생 DayOutcome — 12 §2.1 스키마 준수).
- **E2. 서버 백업 동기화**
  - AC1: Given 온라인 복귀, When 자동 동기화, Then 로컬 이벤트가 서버에 업로드되고 실패 시 지수 백오프로 재시도된다.
  - AC2: Given 기기 변경 후 로그인, When 복원, Then 이벤트 로그 전체가 내려와 스트릭이 동일하게 재계산된다(C1-AC1과 교차 검증).
- **E3. 분석 이벤트 계측 + 게이트 대시보드**
  - AC1: Given 핵심 이벤트 사전(12 §4 확정 택소노미: 온보딩 퍼널 `onboarding_start`~`onboarding_completed`(→ 07 §8), `first_checkin_completed`, `checkin_completed`(source=app·widget·timer·backfill), `streak_frozen`, `streak_recovery_accepted`, `streak_milestone_reached`, `notification_opened`), When 각 행동 발생, Then Amplitude에 유저·기기·코호트 속성과 함께 적재된다.
  - AC2: Given 베타 시작, When 대시보드 조회, Then D1/D7/첫 주 체크인 완료율이 주간 유입 코호트별로 분리 조회된다(04 게이트 판정 형식 그대로).
- **E4. 기본 잔디 통계 화면**
  - AC1: Given 체크 기록 존재, When 통계 탭 진입, Then 잔디밭(월 캘린더 히트맵)과 습관별 스트릭이 표시된다.
  - AC2: Given 놓친 날, When 잔디 표시, Then 붉은색·경고 아이콘을 쓰지 않는다(빈 칸 처리 — 03 문서 복귀 연출 원칙).

## 4. 기술 스택 확정안

### 4.1 클라이언트: 네이티브 vs Flutter vs React Native

| 기준 | 풀 네이티브 | **Flutter (확정)** | React Native |
|---|---|---|---|
| 위젯·잠금화면 | 네이티브 그대로 | 위젯 레이어만 네이티브 작성 필요 | 위젯 레이어만 네이티브 작성 필요 |
| 2개월 4스프린트 완주 | 클라 4인 필요 (iOS 2 + AOS 2) | 클라 2인으로 가능 (단일 코드베이스) | 클라 2인으로 가능 |
| 연출 성능 (Phase 1 루티 애니메이션 대비) | 최상 | 상 (자체 렌더러, Rive/Lottie 성숙) | 중 (브리지 병목 사례) |
| 로컬 DB·오프라인 생태 | 상 | 상 (Drift/SQLite) | 중 |

**확정: Flutter(인앱 UI) + 네이티브 위젯 모듈(iOS: SwiftUI WidgetKit + App Intents / Android: Kotlin Glance).**
근거: 위젯은 어떤 프레임워크를 골라도 네이티브로만 작성 가능하므로(WidgetKit은 SwiftUI 전용, Android 위젯은 RemoteViews/Glance 전용) "위젯 때문에 풀 네이티브"는 성립하지 않는다. 크로스플랫폼 페널티가 위젯 레이어에 국한되는 이상, 5인 팀이 8주에 4스프린트를 완주할 수 있는 단일 코드베이스가 우선한다. RN 대비 Flutter는 연출 성능과 오프라인 DB 생태에서 우위. 대안: 시드 확보로 클라 4인 이상 채용 시 풀 네이티브 재검토.

- 최소 지원: iOS 16 (잠금화면 위젯 지원선, 위젯 원탭 체크는 17+ / 16은 딥링크 폴백), Android 8.0(API 26).
- 위젯–앱 데이터 공유: iOS는 App Group 컨테이너의 SQLite 공유, Android는 동일 DB 파일 + WorkManager 주기 갱신.

### 4.3 오프라인 동기화 전략 (요약 — 스키마 상세는 06 문서 규칙 준수)

1. **로컬 우선, 계정 자원은 서버 권위**: 체크인 기록과 스트릭 표시는 로컬만으로 완결된다(오프라인 낙관 판정). 단 계정 공유 자원의 소모(프리즈·회복권)와 XP·드랍 추첨의 **최종 확정은 동기화 시 서버 재계산**(05 §5.1·12 §1) — 멀티 기기 경합에서 판정 분열을 막는다. 서버는 그 외 백업·복원·집계 담당.
2. **체크인은 append-only 이벤트**: 불변 이벤트만 추가하므로 다기기·오프라인 병합에 충돌이 없다. 설정류(알림 시각 등)만 updated_at 기준 LWW.
3. **스트릭 = 이벤트 로그의 결정론적 재계산**: 저장된 카운터를 믿지 않는다. 기기 변경·복원·시간대 이동에서도 동일 로그 → 동일 스트릭. "억울한 스트릭 끊김"은 죄책감 UI 금지 이전에 신뢰의 문제다.

## 6. 개발 원칙 (릴리즈 차단 기준)

1. **온보딩·페이월 상태 머신 QA 최우선 (Pillar 반면교사, 01 문서)**: 온보딩은 단방향 상태 머신으로 구현하고 상태 전이표를 코드 리뷰 필수 산출물로 관리. 완주·중단 재진입·뒤로가기 자동 테스트가 실패하면 배포 금지. Phase 1 페이월도 동일 지위(가격 캐시, 타임아웃 폴백 UI, 닫기 버튼 상시).
2. **오프라인 우선**: 모든 기능 PR은 비행기 모드 시나리오 통과가 머지 조건.
3. **계측 없는 기능 금지**: 분석 이벤트가 DoD에 포함되지 않은 스토리는 완료로 인정하지 않는다.
4. **죄책감 UI 금지 카피 게이트**: 실패·복귀·프리즈 소모 화면의 카피는 PM+디자이너 2인 승인제. 붉은색 경고·비난 어휘 금지(03 문서 원칙).
5. **엣지 표준 테스트셋 상시 유지**: 자정 직전 체크, 타임존 이동, 기기 변경 복원, 월 전환(프리즈 지급) — S1에서 작성하고 매 스프린트 회귀 실행.

## 7. Phase 0 검증 게이트 운영

- **모집**: 목표 코호트 300명, 최소 200명(200명 미만이면 D7 15% 판정의 신뢰구간이 무의미). 채널 — 에브리타임·디스콰이엇·자기계발 커뮤니티 모집글 + 인스타그램 소액 광고(타겟 페르소나 20~35세) + 지인 시드 50명(6주차 프렌즈 베타). 유입 시 시즌·채널 태그를 코호트 속성으로 기록(04 "신년 코호트 왜곡" 대응).
- **측정 기간**: 8주차 공개 베타 시작 후 **4주** — 주당 약 75명씩 순차 유입시켜 마지막 주 유입분의 D7까지 확보(총 5주). 이 기간은 Phase 1 선행 작업(페이월 설계 확정, 라이브러리 콘텐츠 제작, 보증금 법무 검토 착수)과 병행하므로 캘린더 손실이 없다.
- **판정**: Amplitude 코호트 기준 **D7 ≥ 15% AND 첫 주 체크인 완료율 ≥ 50%** (04 문서 게이트 그대로). 매주 월요일 지표 리뷰에서 중간 판독.
- **미달 시**: 수익화 진입 금지(04 원칙). 퍼널 이벤트(A2의 첫 체크 소요 시간, 온보딩 단계별 이탈)로 병목을 특정해 온보딩·코어 루프 재설계 스프린트 2회 후 신규 코호트로 재측정.
